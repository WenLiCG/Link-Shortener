# 服务域名逐项配置检查设计

## 目标

修复已由当前 Worker 正常承接的服务域名被内部健康检查误判为失败的问题；将“目标服务配置说明”改为逐项检查界面，使用户能识别、复查和修复单个配置环节。

## 已确认的问题

`s.g60.net` 的公网 DNS、TLS 和 HTTP 均正常：公开 `HEAD /` 返回 204，`GET /` 返回 200。当前 Worker 的健康检查却使用全局 `fetch()` 请求同一 Cloudflare Zone 的 Worker Route。未启用 `global_fetch_strictly_public` 时，该请求不会走公网 Worker Route，而会绕过 Route 到 DNS 源站；本系统的源站占位地址是 `192.0.2.1`，因此检查超时或失败。

## 范围

- 在 Wrangler 配置中启用 `global_fetch_strictly_public`，使 Worker 内部健康检查按公网入口路由。
- 将目标服务“配置说明”改为四个独立的配置项：Cloudflare Zone、Nameserver、DNS 记录和 Worker Route。
- 每项显示一个状态：已确认通过显示绿色勾；已确认失败显示红色叉；没有足够事实确认显示黄色问号。
- 每项显示针对该项的人工操作说明，且都有“再次配置”和“信息检查”按钮。
- 列表页面原有“重新配置”保留为四项的一键修复；原有“重新检测”保留为公网 HTTP 健康检查。

不增加配置检查历史、独立表或数据库迁移；检查结果仅在弹窗当前会话中显示，持久状态继续使用现有目标服务字段。

## 后端设计

新增目标服务配置项的按项检查和按项配置接口。接口接收目标服务 ID、配置项和动作；动作只能是读取检查或修复配置。

| 配置项 | 信息检查 | 再次配置 | 成功条件 |
| --- | --- | --- | --- |
| Zone | 查找最匹配的 Cloudflare Zone 并读取状态 | 查找 Zone；缺失时创建目标域名 Zone | 找到且 Zone 为 active |
| Nameserver | 读取关联 Zone 状态及当前目标是否为 Zone 根域名 | 根域名：通过 Dynadot 更新 NS，无法自动更新时返回手工指引；子域名：标记为继承父 Zone | Zone active；子域名不要求改 NS |
| DNS | 查询目标主机的 A、AAAA、CNAME 记录 | 写入橙云 A 记录 `192.0.2.1`，清理同名冲突地址记录 | 存在代理 A 记录 `192.0.2.1`，且没有冲突地址记录 |
| Worker Route | 查询精确的 `{host}/*` Route 与绑定脚本 | 创建或更新该 Route，绑定 `WORKER_SCRIPT_NAME` | 存在精确 Route 且绑定当前 Worker |

每次单项操作只执行该项需要的最小前置读取，不调用全量 `repairTargetService()`。接口响应统一返回状态、说明和手动操作文本。成功和失败结果更新现有相关字段；不能可靠持久化的 Route 检查结果只返回给当前弹窗，并标为未知直到用户检查。

## 前端设计

弹窗顶部保留服务域名和总体公网健康状态。主体按固定顺序渲染四行配置项；每行包含：状态图标、项目名称、当前信息/错误、人工操作说明、再次配置按钮和信息检查按钮。

- 打开弹窗时，Zone、Nameserver 和 DNS 根据现有持久状态显示初始结果；Route 初始为黄色问号，避免把未实时验证的信息说成通过。
- 点击“信息检查”只发送该项的只读检查请求并更新该行。
- 点击“再次配置”只发送该项的配置请求；成功后立即更新该行结果，不隐式修复其他项目。
- 按钮在请求期间仅禁用当前行。错误保留在当前行，避免覆盖其他项目的结果。
- 手动说明使用检查接口给出的具体 Zone、记录名、Nameserver 和 Route 信息；信息不足时明确提示先运行该项的信息检查。

## 错误处理

- Cloudflare Token 缺失、权限不足、网络错误或 API 错误均显示为红叉，并给出对应的人工完成步骤。
- Zone 尚未激活、Nameserver 等待传播等暂态显示黄色问号和等待/复查指引。
- 子域名如 `s.g60.net` 使用父 Zone `g60.net`，Nameserver 行应明确显示“继承父 Zone，无需在注册商设置子域名 NS”。
- 健康检查失败不再泄露底层 fetch 细节；仍只写入现有的安全错误代码。

## 验证

- 为 Cloudflare 配置项结果判定新增最小单元测试：DNS 成功/冲突、Route 精确脚本匹配、子域名继承 Zone。
- 为 Wrangler 配置新增断言，确保 `global_fetch_strictly_public` 不会被移除。
- 运行对应 Vitest 测试、完整测试套件、TypeScript 构建和 Wrangler dry run。
- 使用 `s.g60.net` 进行公网 HEAD/GET 复查，确认 HEAD 204、GET 200。
